# COMPONENT RULES: 任务模式与状态契约

> 先检索并复用目标项目组件及实际规范对弹窗、表格、表单、拖拽的要求。以下是设计决策契约，不要求新增后端未支持的业务能力。

## 通用组件

| 决策 | 适用 | 代价与验证 |
| :--- | :--- | :--- |
| 对象边界 | 独立规则、选中对象、操作作用范围可使用边框、弱背景或标题标识 | 去掉后是否会误认修改对象；重复嵌套是否只增加空间占用 |
| 主次操作 | 按任务突出主要动作，保存与发布等不同后果动作保持可发现 | 收进菜单后是否仍能找到并用键盘执行 |
| 状态标签 | 颜色表达业务状态时保留文字/形状；选中与异常不能共用同一视觉含义 | 项目支持的主题及非颜色辨认是否可靠 |
| 表格边界 | 普通列表可弱化线条；矩阵、分组列和易串行内容保留必要分隔 | 大数据真实长度下是否读错行列 |
| 文本截断 | 表格单元格优先复用项目已有的截断与完整文本展示能力；详情正文可断行 | 截断后是否能通过键盘/触屏获取全量信息 |

需求说明描述用户可见的行为与状态，并引用项目实际规范；组件拆分、数据流和代码组织由前端实施决定。

## 复杂表单与规则配置

适用于多项独立配置和长规则表单。每项配置的类型、实体标识、适用条件及编辑/提交边界保持独立。根据配置数量选择目录、分组、搜索或就地定位；对象名称与当前状态应始终可辨。

| 状态 | 界面需要回答的问题 | 验证 |
| :--- | :--- | :--- |
| 查看中 | 当前规则是什么？是否生效？操作作用于哪项？ | 跨项切换后对象标识仍明确 |
| 修改中 | 哪些字段变了？是未保存、已保存还是待发布？ | 有实际草稿/发布能力时分别展示，不能混用反馈 |
| 校验失败 | 哪一项错误、如何定位和修正？ | 键盘可到达错误项，长表单能定位 |
| 保存中/失败 | 请求是否处理中？失败后输入还在吗？如何重试？ | 防重复操作，失败不丢输入 |
| 保存成功 | 保存了什么？是否已生效或尚有后续步骤？ | 反馈与真实接口状态一致 |

编辑载体按 `UX_PRINCIPLES.md` 选择。若业务不支持草稿、发布或撤销，对应状态不应作为必备功能强行加入。

## 价格矩阵与数据表格

- 行/列标题、当前单元格和单位应保持可辨；列分组、冻结或分隔线由真实规模和串行风险决定。
- 数值格式、货币、精度与零值沿用业务契约；可编辑性不能仅靠 Hover，焦点与触屏需有稳定入口。
- 批量粘贴或调整前说明影响的行列范围；选中、编辑中、错误、保存中、部分失败和成功各有不同反馈。
- 校验失败定位到单元格，失败后保留未提交内容；部分成功不得显示为整体成功。跨页选择和 URL/筛选状态按宿主表格契约处理。
- 验证用真实长标题、大额金额、空值、0、长 ID 与边界行列检查扫描、编辑和错误恢复。

## 监控看板与异常工作台

- 每项指标说明口径、时间范围与来源；刷新状态、数据延迟/过期、无数据、无权限、加载失败不能混为同一空状态。
- 异常严重度基于已确认阈值；颜色、文字和排序共同表达优先级，选中态不冒充异常态。
- 图表下钻仅在有真实任务和数据时提供；筛选联动明确影响范围、清除方式及返回后的上下文。
- 监控与并列比较可采用不同布局；小屏重排时保留告警、时间口径与任务入口，不靠缩小文字解决密度。
- 走查指标读取、异常定位、过滤、进入详情、返回，以及数据过期或请求失败时的判断。
