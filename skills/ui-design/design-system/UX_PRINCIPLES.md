# UX PRINCIPLES: 信息可见性与任务连续性

> 信息分层改变的是展示方式，不改变实体、权限、校验或提交契约。

## 决定默认显示什么

先核对：用户当前必须作出什么判断、哪些数据要并列比较、漏看哪些信息会导致错误，以及用户是否需要长期监控。高频信息通常直显；低频但关键的依据也应在决策时可见。展示层级可按任务切换，不按固定的 80/20 比例或字段数量分配。

| 层级 | 适用 | 代价与例外 | 验证 |
| :--- | :--- | :--- | :--- |
| 默认直显 | 对象身份、有效状态、当前操作及判断所必需的依据 | 过多会影响扫描；不应把必要状态藏入 Hover | 首屏能否辨认对象、状态及下一步 |
| 就近展开 | 一次只看一项、内容短且需保留上下文 | 多项并列核对时反复展开成本高，应考虑并列展示 | 是否反复切换或依赖记忆比较 |
| 独立区域 | 长任务、大矩阵、审计详情或需要可分享的链接 | 需要明确返回路径和上下文恢复 | 返回后筛选、定位和未保存状态是否保留 |

Hover 可以增强发现性，不能是唯一入口；点击、键盘焦点与触屏必须能访问同一关键信息和操作。

## 选择编辑载体

| 载体 | 优先使用 | 注意代价 |
| :--- | :--- | :--- |
| 行内展开 | 短编辑、强依赖当前行 | 保持滚动位置，避免多行展开后失去对象定位 |
| 抽屉 | 需保留列表上下文、详情规模适中 | 遮挡主区，不宜承载宽矩阵或跨项比对 |
| 独立页面 | 长任务、复杂校验、大表格、独立 URL | 返回后恢复筛选、滚动和对象选中 |
| 并列面板 | 高频切换、持续比较多对象 | 小屏须转换为可定位的单列或切换视图 |

## 反馈与恢复

- 将草稿、保存、提交、发布、审核等状态按实际业务区分；不存在的能力不得自行设计成已可用的操作。
- 保存中防止重复操作；失败时保留输入和错误定位；离开有未保存内容时依据宿主与业务规则提示。
- 对普通可撤销操作可采用撤销反馈；不可撤销或影响广泛的操作按实际影响范围确认。确认、撤销或发布能力以系统契约为准。
- 搜索、筛选、分页、选中项与 URL 的关系需有明确约定；返回和刷新不能无故抹去任务上下文。
