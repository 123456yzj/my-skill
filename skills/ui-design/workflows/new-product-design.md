# 新页面与功能模块需求设计

将业务目标形成页面或模块的功能结构、交互方案和验收任务。交付深度随复杂度决定，普通页面无需走完整产品规划。

## 输入

基本需求、用户与场景、已有业务规则、数据契约和项目设计系统。没有确认的数据能力、阈值或操作后果列为待确认，避免把设计建议当成系统已有功能。

## 步骤

1. **任务与范围**：按 [ui-analysis](../methods/ui-analysis.md) 确定用户要完成的任务、关键判断和功能边界。可衡量目标使用已确认口径，不制造指标或提升比例。
2. **功能与信息结构**：按 [information-architecture](../methods/information-architecture.md) 确定页面、区域、信息层级、导航和操作对象。以用户任务划分功能编号。
3. **交互决策**：按需读取 [ux-architecture](../methods/ux-architecture.md)，安排进入、查看、编辑、确认和返回路径。明确布局直接采用；确有不同路径再比较。
4. **视觉与状态**：按需使用 [design-system-builder](../methods/design-system-builder.md) 和 [visual-system-designer](../methods/visual-system-designer.md)，沿用项目规范，补齐界面状态、适配和必要视觉说明。
5. **功能与契约细化**：使用 [requirement-handoff](../methods/requirement-handoff.md)，逐项明确位置、初始、触发、结果、字段联动、权限、校验、数据映射和恢复行为。
6. **验收与交付**：汇入 [需求说明模板](../templates/requirements.template.md)，为每项功能准备正常及适用边界场景、前置数据和可判断预期。
7. **交付复核**：按 [design-quality-gate](../methods/design-quality-gate.md) 检查任务、状态和接口一致性，分清可实施与待确认部分。

## 交付检查

- 页面与功能划分是否支持用户任务，操作后果与实际业务一致。
- 必需信息和低频关键操作是否保留，字段和关联数据是否有真实依据。
- 字段联动、错误恢复、返回上下文和未保存行为是否明确。
- 新增设计决策是否必要，受影响设备与项目支持的主题是否有要求。
- 每项可实施功能是否关联验收场景，缺失契约是否可定位。

设计结果进入同一需求说明；组件拆分、状态管理与代码实现由前端根据项目决定。接到实现结果的复核任务时，再对照说明和证据检查偏差。
