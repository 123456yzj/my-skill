# 数据驱动的功能与交互设计

将 API、DTO、Schema 或 JSON 的字段含义转为用户能理解和操作的界面需求。数据字段是依据，不自动等于界面元素或可编辑能力。

## 输入

实际字段定义、接口行为、枚举说明、用户任务及适用权限。只给字段而没有查询或更新行为时，说明可形成展示需求、操作功能仍缺哪些契约。

## 步骤

1. **语义与实体**：按 [data-ui-designer](../methods/data-ui-designer.md) 核对标识、关联、状态、单位、精度和时间。未知业务含义先检索，仍不明确则澄清。
2. **展示与操作映射**：按需读取 [information-architecture](../methods/information-architecture.md)，区分展示、查询、编辑、审计和仅供提交的字段。字段存在不代表可编辑或可筛选。
3. **形式选择**：按任务决定表格、矩阵、详情、图表或比较视图；可参考 [ux-architecture](../methods/ux-architecture.md)。计算与聚合须有已确认口径，保留独立实体及操作边界。
4. **边界与状态**：定义空值、零值、长文本、大整数、无权限、过期、加载和错误如何表达；格式依据数据类型和用户需求。
5. **功能细化**：使用 [requirement-handoff](../methods/requirement-handoff.md)，说明显示位置、操作触发、字段联动、提交映射和失败恢复。
6. **需求与验收交付**：使用 [需求说明模板](../templates/requirements.template.md)，将每项功能与数据依据、验收场景关联。按 [design-quality-gate](../methods/design-quality-gate.md) 检查完整性。

## 验收任务重点

- 业务名称、枚举含义与实际契约一致。
- 金额、数量、时间和百分比等格式符合实际单位、精度和时区。
- 标识符不因数值转换或格式化丢失精度与含义。
- 空值、零值与空集合按业务含义区分，不相互冒充。
- 展示汇总保留实体、权限、校验与独立编辑/提交边界。
- 筛选、编辑和联动的正常与异常行为明确，计算检查缺失值和零基数。

需要详细数据映射时，将 [数据表达模板](../templates/data-visualization.template.md) 的相关段落纳入当前需求说明。输出验收任务不等于已经执行测试。
