# 局部功能与界面改善

适用于字段添加、联动规则、局部操作及间距、截断、主题等明确问题。交付受影响范围的功能说明和验收场景。

## 输入

用户要求、目标页面或区域、现有行为及可读取的字段/接口契约。视觉问题可提供截图或运行页面；缺少资料时从项目核实，仍影响行为选择的缺口定向澄清。

## 步骤

1. **定位变化**：指出现状、期望结果、影响对象和范围。简单加字段无需整体诊断或新布局。
2. **核实契约**：确认字段含义、只读或可编辑、枚举、默认值、空值、权限与提交行为。后端字段存在不自动产生筛选或编辑功能。
3. **细化交互**：读取 [requirement-handoff](../methods/requirement-handoff.md)，定义位置、触发、结果和边界；联动区分主动修改、回填、重置、失败及连续操作。
4. **补充必要界面要求**：视觉变化按需读取 [visual-system-designer](../methods/visual-system-designer.md) 与 [clean-ui-taste](../methods/clean-ui-taste.md)。按任务判断主次动作、边界、密度和完整文本访问方式，不固定按钮数量或样式类。
5. **交付局部需求**：以 [需求说明模板](../templates/requirements.template.md) 裁剪到本次范围，列出 `REQ` 与对应 `AC`、数据依据和待确认问题。
6. **检查可执行性**：读取 [design-quality-gate](../methods/design-quality-gate.md)，确认实施无需猜关键行为，验收预期可判断。

## 验收任务重点

- 新字段的展示、默认、回填、空值及适用的权限与校验。
- 联动字段的清空/保留、选项、必填性和提交值变化。
- 加载、失败、重试及快速操作的最终状态。
- 视觉改动的真实长内容、完整文本入口、焦点和受影响视口/主题。

只指定本次相关验收场景。需求交付就绪与功能实现、测试通过分别报告。
