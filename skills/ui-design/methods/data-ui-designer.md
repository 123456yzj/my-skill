# 数据语义与界面表达

从“实际数据 → 业务含义 → 用户任务 → 界面行为”形成需求。字段契约提供事实，显示、筛选和编辑能力仍需要业务与接口依据。

## 核对内容

1. **语义与实体**：标识、关联、枚举、生命周期、权限和提交边界。技术名不能替代业务解释。
2. **使用方式**：展示、选择、查询、编辑、审计或仅用于请求。按实际用户任务决定，不按字段数量生成界面。
3. **格式**：类型、单位、货币、精度、时区和地区格式。标识符保持原义，大整数避免精度损失；数字分组用于适合阅读比较的数值。
4. **特殊值**：零、空值、未提供、空集合和无权限按契约区分。零值不显示为空；空值占位应符合其实际含义。
5. **计算**：只有服务任务且有口径时才增加变化率、汇总或衍生指标，核对基准、单位、缺失值和零分母。
6. **操作**：校验、联动、请求和提交语义按实际定义记录。展示汇总不合并独立业务对象。

## 表达选择

- 业务界面使用用户可理解的名称；开发、审计或数据工具需要原始字段名时可保留并解释。
- 表格、矩阵、图表与详情根据比较和操作任务选择。专业宽表可保留，需说明定位、滚动与完整内容访问方式。
- 文本折行或截断按容器与使用方式选择，保留键盘/触屏获取完整内容的入口。
- 加载反馈按等待时长和项目模式选择；失败说明影响、输入保留与恢复行为。
