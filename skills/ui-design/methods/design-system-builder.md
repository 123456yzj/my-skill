# Design System Builder

核对项目已有设计系统，仅在规范不足以表达新增决策时补充必要设计要求。结论汇入当前需求说明；需要长期维护的共用决策可提出纳入项目规范的建议。业务与权限契约优先，已有 [设计规则](../design-system/) 是共享原则与参考。

## 输入与步骤

1. 核对宿主主题、组件库、现有业务实体、权限和操作后果。
2. 对有争议的设计选择说明目标、适用场景、收益、代价及验证：例如规则是否用独立边界，长编辑用抽屉还是独立页面。
3. 仅补充该模块特有的语义颜色、排版、密度和状态组合；按项目支持的主题说明对比度要求，不能复制一套固定配色。
4. 与 [`COMPONENT_RULES.md`](../design-system/COMPONENT_RULES.md) 的复杂表单、矩阵或看板模式核对查看、编辑、错误恢复和返回路径。不假设尚无接口支持的草稿、发布或撤销能力。
5. 在需求说明中记录与项目规范不同的理由、需要确认的选择及验收方式；普通局部任务直接复用已有规范。

可将 [设计决策骨架](../templates/design-dna.template.md) 的相关段落纳入当前说明；不得用主观产品风格代替业务任务依据。
