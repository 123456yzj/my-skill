# 需求交付检查与设计结果复核

依据 [质量标准](../design-system/UI_QUALITY_STANDARD.md) 区分两项任务：需求说明是否可交付，以及实现结果是否满足说明。交付设计不要求先获得尚不存在的运行证据。

## 需求说明检查

1. 核对用户目标、范围及实际业务/数据依据，区分确定要求与建议。
2. 检查每项 `REQ` 的位置、初始、触发、结果和适用状态，尤其是字段联动的回填、重置、失败与连续操作。
3. 检查权限、校验、接口映射、操作后果及独立提交边界是否一致。
4. 检查必要布局、文案、适配与可访问性要求是否明确，避免固定样式代替行为说明。
5. 检查每项功能是否关联可复现的 `AC`，步骤和预期是否足以判断；环境和数据缺口需可定位。
6. 报告可交付范围、需要补充的条目和关键未决事项，不以主观评分代替缺口。

## 实现结果复核

仅在用户要求复核且有实现或测试材料时进行。按 `AC` 对照实际走查、截图、契约及测试证据，指出满足、偏差和未验证项。源码推断应标明，不能据此宣称实际交互测试通过。

局部任务只检查相关范围；业务错误、必要操作不可达或数据丢失优先指出。纯视觉偏好作为建议，不能单独判定失败。实际测试执行与工程修复由对应任务完成。

可将 [复核模板](../templates/ui-review.template.md) 用于整理结果，不强制新增记录文件。
