# 操作路径与布局决策

依据任务、信息比较、编辑范围和设备条件选择布局与操作路径。具体方案形成当前需求说明的一部分。

## 何时需要

任务确有不同导航、阅读或编辑路径时使用。用户已指定合理布局、已有模式可复用或仅改局部字段时，核对约束后直接细化行为。

## 决策步骤

1. 明确对象数量、信息关系、连续操作、跨项比较及返回需求。
2. 核对项目导航、表单与详情模式，以及适用视口和输入方式。
3. 确有选择时比较有实质区别的方案，数量按任务决定。可选模式包括并列面板、行内展开、抽屉或独立页面，选择依据见 [UX 原则](../design-system/UX_PRINCIPLES.md)。
4. 比较各方案支持哪些任务、有哪些空间与操作代价，依据实际任务作决定。无需虚构分数或预设优胜方案。
5. 细化默认、选择、编辑、确认、取消、失败与返回路径，以及相关键盘/触屏行为。

## 交付

- 页面/区域结构，可附线框或操作流程图。
- 每项操作的入口、前置条件、作用对象、结果和状态变化。
- 返回后筛选、定位、选中及未保存内容的处理。
- 受影响视口下的结构变化，必要的焦点与完整内容访问方式。
- 有争议的选择及依据、需要确认的部分。

可用 [方案比较模板](../templates/ux-proposal.template.md) 在需求说明中记录必要取舍。模板不指定固定布局、尺寸、方案数或结论。
