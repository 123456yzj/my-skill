# 需求与界面诊断

识别用户要完成的任务、现有行为与期望变化，为功能说明提供依据。普通字段添加只核对相关位置与行为，不强制整体诊断。

## 输入

用户要求、反馈、页面或截图、可读取的源码与数据契约。区分用户明确要求、实际观察、代码推断、设计建议和未知信息。

## 判断方法

1. **用户任务**：谁在什么场景完成什么操作，需要判断或确认哪些信息。指标仅在确实服务任务时定义。
2. **当前与期望**：说明在哪个区域、哪个状态出现问题，造成什么任务成本；明确用户期望的行为或待确认选择。
3. **业务边界**：核对对象、权限、状态、校验、操作后果和提交边界。一次局部要求不扩展为系统重构。
4. **问题依据**：定位信息难找、比较困难、入口不可达、误操作或失败恢复问题。视觉元素只有在影响任务时作为问题，不能按卡片、颜色或边框形式直接判错。
5. **范围与依赖**：判断哪些功能可以形成实施条目，哪些需要业务、接口或布局决策。普通需求不必套完整分类或固定任务比例。

## 输出到当前需求说明

- 用户目标、范围及相关原始要求。
- 当前行为与需要变化的功能、区域和状态。
- 已确认的规则、事实依据及必须保留的能力。
- 待确认问题、影响条目和可独立继续的部分。

复杂诊断可将 [诊断模板](../templates/ui-analysis.template.md) 的适用段落并入需求说明。不要仅写“更高级”“更清晰”，应给具体行为或有依据的设计方向。
