# Clean UI Taste

适用于复杂表单、表格和看板的视觉整理。先识别用户任务，再检查颜色、边界与留白是否有实际作用；宿主主题及 [设计规则](../design-system/) 优先。

| 调整对象 | 可简化的情形 | 应保留的情形 | 检验问题 |
| :--- | :--- | :--- | :--- |
| 容器/分隔线 | 连续嵌套重复表达相同分组 | 不同费用规则、可编辑范围、矩阵行列边界 | 去除后能否辨认对象和操作范围 |
| 颜色/标签 | 同一状态被多个装饰色重复强调 | 异常严重度、成功/失败、选中及数据图例 | 是否能区分含义且不单靠颜色 |
| 留白 | 空白只增加滚动、不增强分组 | 需要区分流程阶段、复杂表单和危险操作 | 扫描与跨项比较是否更容易 |
| 操作入口 | 同级动作重复占用顶栏 | 保存/发布等后果不同的常用动作 | 收进菜单后能否发现并用键盘操作 |
| 表格线与编辑控件 | 线条对读取无贡献 | 宽矩阵、列分组、易串行数据与可编辑状态 | 真实数据下是否读错、点错 |

普通列表可使用轻边界，但不是所有页面都应无框。长任务可用独立页面，短编辑可用行内展开或抽屉，选择依据见 [`UX_PRINCIPLES.md`](../design-system/UX_PRINCIPLES.md)。颜色与文字优先宿主语义令牌，阅读文字检查对比度；中文表头不因“紧凑”默认降到 11px。

在需求说明中列出真实长名称、空值、金额及项目支持主题的验收要求；复核已有结果时再检查对象定位、状态辨认和错误恢复。仅改变外观却降低任务可用性，不属于有效降噪。
