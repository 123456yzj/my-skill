# Visual System Designer

视觉方案先说明当前任务、实体边界、阅读/比较路径和项目主题，再给出视觉要求。以 [`DESIGN_DNA.md`](../design-system/DESIGN_DNA.md) 的决策表为原则，令牌参考 [`DESIGN_TOKENS.md`](../design-system/DESIGN_TOKENS.md)，任务状态参考 [`COMPONENT_RULES.md`](../design-system/COMPONENT_RULES.md)。

## 设计步骤

1. **确定焦点**：用户要识别哪项对象、判断哪种状态、执行什么操作？明确哪些信息需要同时比较。
2. **选择边界**：独立规则、批量选择、矩阵行列可使用边框或弱背景；仅起装饰作用的重复外壳才简化。比较移除前后对象归属和空间占用。
3. **安排密度**：常规阅读采用宿主标准密度，高频桌面扫描可用紧凑密度；小屏先重排，不靠缩小字号。用真实中文长名称、金额、空值和错误信息检查。
4. **定义语义色**：品牌操作、选中、成功、警告、错误及图例各有含义；不能只靠颜色表达，不能把各类状态一律改灰。
5. **补齐状态**：检查 default、hover、focus、selected、disabled、invalid、loading，以及受影响的保存反馈和数据过期状态；编辑入口在键盘和触屏下仍可发现。
6. **校验可读性**：使用宿主字阶和颜色令牌；普通文本对比度 >= 4.5:1，大文本及必要图形/控件边界 >= 3:1。中文表头不默认使用 11px、`uppercase` 或扩展字距。

## 产出与复查

将必要布局、文案、层级、密度、颜色语义与状态写入对应功能或界面要求章节，说明设计选择的依据与验收方式。例如“各项规则有独立生效周期，使用弱边界区分，验收跨项编辑是否误认对象”。数值比较说明精度、单位和对齐要求，具体样式实现由前端决定。

需求交付时列出受影响视口、项目支持的主题及真实数据验收场景。复核已有实现时才核对实际表现；没有渲染或用户任务证据时只报告设计推断，不宣称体验提升。
