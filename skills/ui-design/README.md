# UI 与功能需求设计

入口为 [SKILL.md](SKILL.md)，名称为 `ui-design`。将用户需求与已有业务、字段和接口契约整理成前端可实施、测试可验收的当前需求说明。

## 输入与交付

可提供基本需求、目标页面或区域、现状材料、后端字段/操作契约和项目约束。已在项目中的资料由 agent 检索；缺少关键业务含义时列出具体问题。

主交付是一份需求说明，包含：

- `REQ` 功能编号、页面区域、初始状态、触发、行为和字段联动。
- 权限、校验、数据映射、状态反馈及失败恢复。
- 必要布局、视觉与设备适配要求。
- `AC` 验收编号、关联功能、前置条件与数据、操作及预期结果。
- 实施依赖、待确认项和交接范围。

格式见 [需求说明模板](templates/requirements.template.md)。沿用目标项目现有需求文档位置与版本约定；没有约定时先提出相对落点。用户仅要求讨论时在对话中交付。

前端负责代码与工程选择，测试负责执行验收；本 skill 形成两者的共同依据，按要求可复核实际结果。仅生成场景不表示测试通过。

## 安装与调用

将整个技能目录放入所用助手支持的技能目录，保留内部相对位置；按助手要求刷新或重启。也可让助手直接读取 `SKILL.md`。

> 使用 ui-design，根据这份基本需求与接口契约，整理前端功能说明和验收场景。明确页面区域、字段联动、初始化回填及失败行为，先列出需要确认的业务问题。

## 验证范围

格式与内部链接可以静态检查。以下为流程审查场景，实际模型执行效果需通过宿主任务演练验证：

| 输入情况 | 应有交付 |
| :--- | :--- |
| 明确增加一个只读字段 | 局部 `REQ`、数据格式/空值规则和对应 `AC`，无需整体设计 |
| 字段联动 | 区分主动修改、回填、重置、加载失败和连续操作；预期结果可判断 |
| 仅提供字段类型、未提供更新行为 | 可确定展示部分，编辑功能列出缺失契约，不补造接口 |
| 整体页面或看板 | 按需补结构、状态、联动与适配，并汇入同一说明 |
| 用户仅要求讨论 | 对话交付，不创建需求文件或执行实施任务 |
| 尚无实现或测试证据 | 需求可交付与结果未验证分别说明 |

此 skill 不依赖固定业务、项目目录或技术栈；方法和参考按需读取。
